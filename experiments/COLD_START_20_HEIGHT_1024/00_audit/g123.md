## 2. What each stage actually does

All four stages use **one** production engine: the greedy per-route
`local_reroute.reroute_one` (called from `optimizer.Optimizer.run_round`,
`optimizer.py:67-139`) on top of the incremental exact world
`world_adapter.RouteWorld`. The design modules `motion_primitives.py`,
`corridor_search.py`, `xyz_search.py`, `route_state.py` are **not** used by the
G1/G2/G3 loop (only by the dev self-check `router_selfcheck.py:16-23,74-77` and
by the P2 Z-only helper path in `run_router_validation.py`). The production XY
candidate family is the `layer2d` R15 family library (line / quarter arc / short
S / L / Z / U / detour / staircase), including the local planar **multi-arc
short-S** override controlled by `layer2d.MULTI_ARC_POLICY` (`layer2d.py:229-241`,
used at `local_reroute.py:126`, `layer2d.py:1215`).

### 2.1 Search degrees of freedom per stage

| Stage | Manual-U (368) | Non-manual (656) | What is movable |
|---|---|---|---|
| **G1 "manual frozen"** | completely frozen: excluded from the candidate list (`run_g1.py:60-76`; only routes with empty `manual_group` are candidates) | full XYZ joint re-route | for non-manual: target height (any of the 21 heights / interface-direct), lead lengths, entire XY corridor; body height + XY may change together |
| **G2a "manual group reheight"** | 8 upstream groups (`manual_reheight.GROUP_ORDER`, `manual_reheight.py:23-24`) may each move to **one shared new body height**, XY body primitives kept byte-identical (`manual_reheight.feasible_heights` `:58-83`, `group_shared_heights` `:104-114`, `build_shift`→`route_builder.shift_height_keep_xy` `:86-88`) | full XYZ joint re-route (656) | + one shared Z per group; XY body and A/B landing points fixed |
| **G2b "manual route reheight"** | each of the 368 manual routes may pick its **own** body height, XY body kept (`manual_reheight.reheight_one_route` `:217-239`, `apply_route_reheight` `:242-247`) | full XYZ joint re-route (656) | + per-route Z; XY body fixed |
| **G3 "manual full xyz"** | fully optimisable, same engine and same freedom as non-manual (`run_g3.py:58-61`, `experiment.run_all_route_optimizer` `experiment.py:64-78`: candidate ids = all 1024 routes sorted by crossing count) | full XYZ joint re-route | everything except route identity/ports; `manual_policy='fully_optimizable'` |

Implementation detail of G2's `height_only` contract
(`route_builder.shift_height_keep_xy`, `route_builder.py:223-256`): the two body
landing points `A = port + (lead + f(z_old))·inward` are kept fixed, the lead is
recomputed as `lead' = lead + f(z_old) - f(z_new)` and the two R15 end
transitions are rebuilt; the body flat primitives are reused verbatim. Because
the 21H manual leads are all exactly the 0.25 mm process minimum, only heights
towards the interface are reachable (report:
`reports/G2_report.md:16-35`, `reports/README.md:65-71`). The 20H baseline may
differ here: the reachable set must be recomputed from the 20H Phase-2 solution
(the code does this automatically, `manual_reheight.feasible_heights`).

### 2.2 Candidate construction (production engine)

`local_reroute.propose` (`local_reroute.py:200-305`) per route:

1. `old_events` = exact current events of the route over its planes; if 0, skip
   (`no_current_crossings`, `:215-218`).
2. **Target options** (`target_options`, `:53-87`): the best
   `max_target_layers=3` body planes ranked by `(plane load count, |z-cur_z|, id)`
   → `kind='migrate'`; plus, if the route is currently lifted,
   `kind='direct'` (convert to an interface-direct body at the interface height)
   when `allow_direct`; plus `kind='xy_only'` (same height, new XY corridor) —
   for a route already at an interface plane this becomes `direct_xy`.
3. **Lead-pair ladder**: `_lead_pair_candidates` (`:90-106`) = current leads plus
   `route_builder.LEAD_CANDIDATES` pairs, bounded by `max_lead_pairs=2`.
4. **XY candidates** (`xy_candidates`, `:112-161`): builds `layer2d._LayerRouter`
   objects per target plane (`:129-132`; the plane's existing flat chains are
   passed as `initial_routes`, transitions within ±0.12 mm as obstacles), streams
   the exact R15 family library candidates via `_iter_candidates`
   (`max_candidates` = 220 pre-screen / 420 full pass), pre-ranks them with the
   O(1) grid crossing pre-rank `RouteWorld.fast_crossings` (`world_adapter.py:321-322`,
   `PlanePrimGrid` `:52-117`), keeps the top `d56_top=24`, runs the frozen strict
   D56 index evaluation + obstacle check + self-clearance, and keeps
   `bodies_per_pair=2`.
5. Cheap pass over all target options (prescreen cfg `PRESCREEN_CFG`,
   `local_reroute.py:35-43`), then the exact full pass on the best
   `max_combos=2` options (`:247-305`), each combo with up to `max_lead_pairs`
   lead pairs and `max_eval=2` bodies; exact candidate evaluation =
   true-3D World check + exact per-plane crossing delta
   (`world_adapter.evaluate_candidate`, `world_adapter.py:391-401`).
6. **Acceptance**: keep the lexicographically best `(crossing delta, length)`
   (`local_reroute.py:299-301`); `early_stop_delta=6` stops after a ≥6-gain
   combo (`:302-304`); `reroute_one` only commits when
   `delta <= -min_delta` (`min_delta=1`, `:318-330`), i.e. a candidate must
   strictly remove ≥1 crossing event.

Candidate **route assembly** (exact R15 only, no polylines):
`route_builder.build_lifted` (`:114-129`, lead + R15 S-curve + body + S-curve +
lead via `native3d.fanout.candidate_transitions` + `assemble.assemble_route`
`route_builder.py:22-26`), `build_direct` (`:132-146`), body-only replacement
`replace_body_keep_fanout` (`:202-220`), `shift_height_keep_xy` (`:223-256`),
and multi-height/multi-arc body insertion `insert_height_plan`
(`:259-278`, `native3d.excursion2.insert_excursion_general`) — the latter is not
used by G1/G2/G3 (only by the P2 "Z only" arm of `run_router_validation`).

### 2.3 Acceptance criteria / cost / budgets

* Global objective: minimise the **same-layer crossing event count** under the
  frozen strict-D56 definition (`native3d.crossing_cache`, grouped by physical
  z, `world_adapter._recount_planes` `world_adapter.py:196-211`); hard
  constraints R15 / 50 µm true-3D clearance / glass / port identity / structure
  are enforced by `l3d.world.World.check_route` inside `check_3d`
  (`world_adapter.py:350-360`) and are never relaxed.
* Per-candidate objective: `(delta, length_mm)` lexicographic, delta = exact
  event-count change (not pairs); ties → shorter route.
* G2 height choice (G2a) adds a second objective: lexicographic
  `(crossing delta, crowding score)` where crowding = Σ n² over height usage
  (`manual_reheight.crowding_score` `:131-143`, `choose_group_height`
  `run_g2.py:60-101`); a group may pay up to `--delta-budget 80` crossings
  immediately (`run_g2.py:97-100`).
* G2b per-route height accepts any route whose exact delta ≤
  `--route-delta-budget 2` (i.e. temporary +1/+2 crossings are allowed, negative
  deltas obviously; `run_g2.py:128-151`) — this is why the G2b height moves
  themselves raised crossings 1337→1367 before the non-manual re-route recovered
  24 (see `warmstart_chain.log:73-77`).
* Per-route budget for the production engine is in `local_reroute.DEFAULT_CFG`
  (`local_reroute.py:18-32`); `run_router_validation` uses a near-identical
  `ENGINE_CFG` (`run_router_validation.py:89-103`; note `max_candidates=400` vs 420).
* Aggregated budget: `Optimizer.run(candidate_ids, rounds, round_seconds,
  max_accepts)` (`optimizer.py:141-157`); wall-clock stops inside
  `run_round` (`:73-80`). Historical budgets: G1 `--rounds 2
  --round-seconds 1200 --top 656`; chain G2a 300 s, G2b 240 s, G3 500 s
  (`run_warmstart_chain.py:55-57`); G3_cold 1200 s.

### 2.4 Rollback and checkpoints

* Everything is **transactional at the route level**: `evaluate_candidate`
  does not mutate; `commit` re-adds the route to every per-height D56 index and
  recounts (`world_adapter.py:403-457`); batch operations re-validate with the
  shared 3D world and rebuild the world cache if it was polluted
  (`batch_evaluate` `:460-496`, `batch_commit` `:498-545`,
  `batch_crossing_delta` `:547-576`).
* `local_reroute.reroute_joint` (`:353-419`) rips up 2-3 routes, re-plans them
  sequentially, rolls the whole transaction back on any failure or if
  `gain < min_gain` (deep-copied routes + rebuilt indices). Used by P1 and
  available to the optimizer but not used by G1/G2/G3.
* Checkpoints: every 25 accepted changes the optimizer writes
  `paths.DIRS['checkpoints']/checkpoint_%04d/{routes_l3d.json,assignment_1024.csv,checkpoint.json}`
  (`optimizer.py:117-124, 160-167`). **Known defect:** the checkpoint directory
  is global, not stage-scoped, so a later/parallel stage overwrites another
  stage's checkpoints. In the archive, `checkpoints/checkpoint_0025..0125`
  (totals 2007/1803/1696/1609/1514, seconds 127.6/269.9/367.4/543.1/837.4,
  mtimes 12:49-13:00) come from **G3_cold**, while `checkpoint_0150`
  (total 1409, seconds 1258.5, 13:02) is G1's round-2 checkpoint; G1 and G3_cold
  ran concurrently. The 20H rebuild should namespace checkpoints per stage.
* No automatic resume: `run_g1`/`run_g2`/`run_g3` always reload their start
  directory from scratch (`experiment.load_state` `experiment.py:23-31`); only
  the scripts re-run from a checkpoint copy by hand (the G4 package has a real
  `--resume` mechanism, `g4/c0_continue.py`, not used by G1-G3).
* After every stage the runner calls the independent validator in-process
  (`experiment.validate_stage` `experiment.py:91-102`; G1: `run_g1.py:121-131`
  which **only logs** validation failures, G2: `run_g2.py:226-231/257-262`,
  G3: `run_g3.py:71-78`).

### 9.1 Mandatory: bootstrap-first entry points (import-order seam)

Every `xyzrouter` module does `from ..reheight21 import model as M` at import

`world_adapter.py:28`, `optimizer.py:13`, `experiment.py:10`, `run_g1.py:24`,

  swapped, and `route_builder.PLANE_Z/BODY_PLANE_IDS` would be frozen to 21H.
