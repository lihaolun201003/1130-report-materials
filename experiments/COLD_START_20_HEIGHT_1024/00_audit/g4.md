## 0. Verdict and top findings

1. **The G4 engine is height-table-agnostic in its *search* logic**, because all plane
   geometry is read through `reheight21.model` via `xyzrouter.route_builder` /
   `xyzrouter.world_adapter`: `RB.BODY_PLANE_IDS`, `RB.PLANE_Z`, `M.layer_stack()`,
   `M.PLANE_IDS`. Once `coldstart20.bootstrap` has installed `model20`, the *search*
   sees 20 planes and 18 body heights with no algorithm change.
2. **The G4 *entry points and experiment wiring* are not 20H-aware.** `g4/paths.py`
   hardcodes the 21H G3 start (`outputs/.../XYZ_JOINT_G123_1024/best_valid`,
   SHA `711cf910…`, `START_CROSSINGS = 1322`) and the 21H archive root
   (`experiments/xyz_joint_g4_1024`); `contract_audit` / `independent_metrics` /
   `metrics_collect` / `report_g4` / `archive_g4` / `fair_runner` carry 21H literals
   (1322/1185/1189/1204/1253/19/21/368/`0.5`/old SHAs). The inventory is §4.
3. **A silent 21H/20H mix is possible today** (this is the single most dangerous finding):
   with `coldstart20.bootstrap` installed, `g4.paths.load_start()` still loads the 21H G3
   route file. Measured in a read-only probe: the state builds fine
   (`validate_all() -> valid=1024`) but it has **21 distinct flat heights, 0 of which are
   20H model heights, and 50 routes at z=+0.65 (deleted plane L19)**. `load_start()` then
   reports `crossings=1322`. A 20H run must fail fast here, not silently "run".
4. **`START_CROSSINGS` is already a lie for chain starts** in the current code:
   `g4/paths.load_start()` returns `crossings=int(START_CROSSINGS)` regardless of the
   directory, and `arm_base.load()` logs `GP.START_CROSSINGS`. Evidence: the chain link
   started from the 1294 checkpoint logs `crossings=1322`
   (`08_progressive_chain/fair_runner.log`), then loads a state with 1294.
   `state.start_total` (the equal-budget patch) is the only correct value; use it
   everywhere and delete the constant as a data source.
5. The six-validator/audit layer that must certify 20H results is
   `validate_xyz` (frozen independent validator, subprocess), `independent_metrics.py`
   (independent geometry/contract recomputation) and `contract_audit.py` (six mandatory
   quantities + code-evidence citations + revalidation). Their 20H deltas are small and
   enumerated in §5; **none of the physical thresholds may change**.
6. `best_valid` is a lightweight snapshot (`routes_l3d.json`, `assignment_1024.csv`,
   `SHA256.json`; `summary.json` only when `include_stats`), only written when
   `state.total` strictly decreases and only from a committed, verified transaction;
   checkpoints are full-arm snapshots every 50 accepts or 10 min; `--resume` restores the
   newest `checkpoints/step_*` and the ledger. Rollback is exact (restores routes+rows,
   recounts only affected heights, asserts no orphan plane entries). §6.
7. 21H wall-clock cost (from logs/`experiment_matrix.csv`): C0 1208.8 s, G4a 1018.7 s,
   G4b 1099.8 s, G4c_frozen 1847.0 s, G4c_free 1840.4 s, G4d ~1354 s (2 sessions; ledger
   106.3 s is session 2 only), chain links 740.5/1230.0/1061.4 s, plus ~20–27 s per
   independent validator. Budget contract: `route_3d_checks=30000`,
   `d56_candidate_evals=120000`, wall `1200/1800/3600` s (§7).
8. **Prerequisite for the 20H G4 chain: a real 20H G3 state must exist** (produced by the
   20H cold-start + native-3D G1/G2/G3 chain into `07_g123/best_valid`). Its SHA and
   crossing count are outputs of that run, not constants. G4 must read them at runtime
   and record them in a `START.json` fingerprint. See §8.

### 3.3 Hard guard is mandatory (evidence of a silent 21H↔20H mix)

every transition, fanout landing and cross-height clearance relation is invalid for 20H.

## 6. `best_valid`, checkpoints, `Ledger`, `Transaction`, rollback and resume

### 6.1 `Ledger` (`g4/ledger.py`, 129 lines)

Plain counter bag (`KEYS` l.26-41, `bump`, `add_float`, `as_dict`, `load_dict`,
`write`, `load`); JSON schema `g4_budget_ledger_v1`; `over_budget` checks
`route_3d_checks`/`d56_candidate_evals`/`wall_seconds`; `budget_fraction` for logging.
It is written:
* at every checkpoint (`arm_base.save_checkpoint` → `checkpoints/step_*/budget_ledger.json`);
* at arm end (`arm_base.save_final` → `budget_ledger.json`, `strategy_stats.json.ledger`);
* by C0 with explicit `d56_candidate_evals=null` + proxy (SPEC 3.2 requirement).
The ledger must be written for 20H exactly the same way; do not synthesize counters.

### 6.2 `Transaction` / rollback guarantee (`joint_world.py`)

Open: deep-copy old routes/rows/groups, `old_total`, `old_pairs`, `old_history_length`,
`transactions++`. `rip_all`: drop routes from true 3D world and from per-height D56
indices; invalidate height caches. `plan`: candidates checked against the *current*
transaction world (`mode='transaction'`), not the old geometry. `place`: re-inserts route
into state + world. `finish`: recount affected heights exactly
(`nonc4.crossings.audit_flat_group`), accept only if all rids placed and
`gain >= min_gain` and `_verify_placed()` has no 3D violation; otherwise
`_rollback`. `_rollback` restores saved routes/rows, drops transaction geometry, recounts
affected heights, asserts no orphan plane entries, `rolled_back++`, truncates history, and
appends a failed transaction record. So: **a partially legal set can never be left behind**;
failed/gain-0 transactions leave state and ledger consistent. `maybe_rebuild_world()`
rebuilds the incremental true-3D World every 150 transactions to bound memory.

### 6.3 `best_valid` (`BestTracker`, `artifacts.py:152-192`)

`best_total` only decreases; `consider()` writes a lightweight snapshot
(`routes_l3d.json`, `assignment_1024.csv`, `SHA256.json`; note: no
`crossing_stats.json`/`summary.json`) to `<arm>/best_valid/` at most every 20 s (or forced
at final). G4c/G4d initialise it from the start state (`alns.run`: `best.consider(state,
note='start')`), so `best_valid` always exists; G4a/G4b call `tracker.force_save` in
`GR.finalize_arm`. Only committed, verified, strictly-improving states are ever written.

### 6.4 Checkpoints and resume

`arm_base.save_checkpoint(tag=None, extra=None)` → `checkpoints/step_NNNNN/` with
`routes_l3d.json`, `assignment_1024.csv`, `SHA256.json` (lightweight snapshot) +
`budget_ledger.json` + `checkpoint.json` (`tag,total,history,ledger,seconds,extra`);

`_maybe_checkpoint`), at stage end (`alns._run_stage` tag `step_%05d % accepts` with

`group_replan.checkpoint`. `latest_checkpoint()` picks the newest `step_*` with
routes+assignment; `ArmContext.load(resume=True)` restores routes/rows **and** the ledger
from that checkpoint. `run_g4c/run_g4d` additionally resume at the correct stage and skip
the finished sweep. C0 uses its own crash-safe resume from `best_valid/` + `progress.json`
