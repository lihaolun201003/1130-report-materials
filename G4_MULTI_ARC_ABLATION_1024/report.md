## 2. 任务二（第 1 步）：现有多圆弧机制审查

### 2.1 代码审查：平面候选生成器与圆弧家族

1024 通道的 XY flat 本体由 `four_side_1024/fanout1024/layer2d.py` 的 `_LayerRouter` 生成（G4 的 `local_reroute.xy_candidates` 直接调用它），候选家族分三类：

| 类 | 家族 | 是否"局部多段组合圆弧" |
|---|---|---|
| `same`（同侧 U 弯） | `U_QUARTER_PAIR`、`U_R15_LIBRARY` | 否（独立转角 / 同圆拆分） |
| | **`U_SHORT_SHIFT`** | **是**（双弧 short-S） |
| `opposite`（对侧） | `OPP_STRAIGHT`、`OPP_Z`、`OPP_Z2_SAME`、`OPP_DETOUR`、`OPP_DETOUR_BACK` | 否（Z 家族两弧之间**有直线**；detour 的弧也各自独立） |
| | **`OPP_SHORT_S`、`OPP_S2_SPLIT`、`OPP_S_Z`、`OPP_Z_S`** | **是** |
| `adjacent`（相邻侧） | `ADJ_L`、`ADJ_Z_TURN`、`ADJ_Z_TURN_LEFT`、`ADJ_Z2_TURN`、`ADJ_DOWN_LOOP`、`ADJ_UP_LOOP`、`ADJ_SIDE_LOOP`、`ADJ_LEFT_LOOP` | 否 |
| | **`ADJ_SHIFT_TURN`、`ADJ_TURN_SHIFT`、`ADJ_SHIFT_LOOP`、`ADJ_SHIFT2_TURN`** | **是** |

所有"是"的家族都通过同一条 move 原语产生：`('S', shift)` → `fslw.geom.short_s()` →
**两个切点相连、转向相反的精确 R15 圆弧**（`theta = acos(1 - d/2R)`）。这正是任务定义的
"同一局部平面转弯/避让区域的多段组合圆弧"。

明确**不属于**该自由度的三类（本实验保留）：

1. **U 型路径不同转角处的独立圆弧**：`Q … L … Q`，弧之间夹直线；
2. **三维 z 升降的双弧 S transition**：`kind='transition'` 的 part，不在 flat 链中，本实验完全不触碰；
3. **同圆拆分**：`middle = 0` 时一个 180° 圆被存成两条 arc 记录（`local_multi_arc_regions` 判定为 `same_circle_split`，不计入多圆弧）。

### 2.2 几何证据：机制**确实被启用**，而且**确实改变了 XY 路径**

对最终合法解做逐段圆弧游程分析（`tools/audit_flat_multi_arc.py`）：

| 解 | flat 弧 | 圆弧游程 | 单弧 | **双弧 S** | **>2 弧组合** | 多圆弧弧数 | 含多圆弧线路 |
|---|---|---|---|---|---|---|---|
| G3 起点（1322） | 1788 | 1441 | 1238 | **123** | **79** | 548 | 197 |
| **G4 最终（1185）** | **1798** | 1453 | 1245 | **131** | **77** | **553** | **202** |

* 202/1024 条线路含至少 1 个真实平面多圆弧区域，共 208 个区域、553 条弧
  （占全部 flat 弧的 30.8%）。
* 因此**不存在"G4 实际没启用该机制"的情况**：它真实存在、真实进入最终解、真实改变 XY 几何。
* 反向自检（`tools/test_multi_arc_policy.py`）：策略关闭后，同侧/对侧/相邻侧三类采样任务的
  **每一个**已构建候选的多圆弧区域数都为 0，且 Z / detour / L 家族仍然存在
  （例如对侧候选由 151 → 105 个，相邻侧 643 → 576 个）。

## 3. 实验设计

### 3.1 单一变量

`G4_ENABLE_MULTI_ARC = 1 / 0`，注入点是 `layer2d._iter_candidates`：

1. 关闭时先按 `('S', shift)` 过滤**候选规格**（省 build 预算）；
2. 再对每个已构建候选做**几何硬门**：任何"切点连续 + 转向相反 + 圆心不同"的圆弧串一律丢弃。

补丁为**纯增量**（110 行新增、0 行删除），不设环境变量时行为与归档完全一致
（`code_changes/g4_multi_arc.patch`）。

### 3.2 起点问题与 Stage-0 转换（本实验最关键的设计决定）

G3 起点解中有 **197 条线路的 flat 几何本身就是用 short-S 建的**。如果只关闭"新候选"的
多圆弧，这 197 条会原样保留（G4 的搜索只改动极少数线路），"取消多圆弧"就没有真正实现。

因此对照组增加 **Stage-0**：对这 197 条线路，用**与 G4 搜索完全相同的 planner**
（`joint_world.PLAN_CFG`，3 个自由高度、2 组 lead、预筛 160/320、`d56_top=16`）在同一个真 3D World
内重规划，接受精确交叉增量最小的合法候选；不合法就保留原几何（本次 residual = 0）。
**不是删弧、不是把圆弧换成折线。**

这就是"用原有单圆弧候选完成真实布线和优化"的操作化定义，代价单独计量（§4.2）。

### 3.3 两组设置

| | on 对照 | off（NoMultiArc） |
|---|---|---|
| 起点 | G3 `711cf910…`（1322） | Stage-0 转换后 `1707e189…`（3967） |
| `G4_ENABLE_MULTI_ARC` | 1 | 0 |
| 连接数 | 1024 | 1024 |
| 玻璃 / 21 高度 / R15 / D56 / 3D 净空 | 不变 | 不变 |
| 搜索 | `G4c_free` 1800 s + `G4d` 1200 s，seed 20261104 | 同（`G4d` 提前停在安全检查点，见 §6.4） |

### 4.2 交叉数变化的完整分解

```
G3 起点                              1322
  + Stage-0 转换（197 条线路重表达）   +2645   →  3967
  + G4c_free（1836 s）                  −447   →  3520
      其中贪心高度迁移 sweep −394（52 次接受），4 个 ALNS stage −21/0/−25/−7
  + G4d（158 s，提前停）                 −36   →  3484   ← G4-NoMultiArc 交付值

on 对照（同一代码、同一预算口径）
G3 起点 1322 + G4c_free（1855 s）−118 → 1204 + G4d（1265 s）−2 → 1202
```

* **转换本身**解释了两组差值的全部：`2645 − 483 + 120 = 2282`（= 3484 − 1202）。
* **搜索并没有变差**：off 组搜索收益 −483，反而大于 on 组 −120（因为它从一个更差的状态出发）。
* 与历史归档 1185 的差值 2299 = 2282 + 17（on 重跑相对归档的可复现性偏差 +1.4%）。

### 4.3 转换代价的几何成因（阈值恰好是 2R = 30 mm）

| 起点解中 197 条含多圆弧线路 | 条数 | 平均交叉增量 | 合计 |
|---|---|---|---|
| 落点横向错位 `|bx| < 2R` (30 mm) | **145** | **+18.25**（中位 +18，99.3% 为正） | **+2646** |
| `|bx| ≥ 2R` | 52 | −0.02 | **−1** |

被选中的替代家族：`OPP_DETOUR` 80、`OPP_DETOUR_BACK` 64、`OPP_Z` 39、`ADJ_L` 12、`ADJ_UP_LOOP` 2。

**为什么是 2R**：两个**相互独立**的 R15 四分之一圆弧（中间夹直线）一次只能把路径横移
`2R + w ≥ 30 mm`；要得到 `0 < |bx| < 30 mm`，最少需要 **4 个**四分之一转角（+x、+y、−x、+y），
纵向至少推进 `4R = 60 mm`，横向还要一个"凸起"。原语法用两个相切圆弧在约 40 mm 的
footprint 内完成同一件事。取消后，这类线路只能走 ≥4R 的绕行环路。

图：`baseline_audit/conversion_offset_vs_delta.png`（横向错位 vs 交叉增量，2R 处断崖）。

## 5. 五个必答问题

**1）关闭多圆弧后，真实交叉数变化多少？**
1185 → **3484**（+2299，×2.94）。同代码 on 对照为 1202，则 1202 → 3484（+2282，×2.90）。
其中 **+2645 发生在"重新表达 197 条继承线路"这一步**，后续搜索收回 483。

**2）哪些物理高度受影响最大？**
Z1 接口层 +294、L8 +232、L7 +226、L10 +198、L6 +183、L20 +152、L11 +140；
同时把原本空闲的 L2/L4/L5 从 0 抬到 96/122/133（绕行线路被迁移到空层后又互相交叉）。

**3）多圆弧究竟通过什么几何机制改变交叉？**
它是**亚 2R（<30 mm）横向错位的唯一紧凑几何手段**。两个独立四分之一圆弧的最小非零横移是
2R=30 mm；小于 30 mm 时，消融语法只能走 4 转角、纵向 ≥4R 的绕行环路。绕行环路扫过的
面积是原 S 形的数倍，在 150×150 的密集层里平均每条多压 18.25 条其它线路。
145 条亚 2R 线路贡献了 +2646；52 条 ≥2R 线路合计只差 −1 —— **断崖精确落在 2R**。

**4）新方案是否增加长度或几何复杂度？**
是，但**长度增加很小、交叉增加极大**：总长 156735.6 → 165059.1（**+5.3%**）；
flat 弧 1798 → 1888（+90，绕行用 4 弧替代 2 弧）；flat 直线 4210 → 4582（+372）；
单线最大交叉 19 → 41；有交叉的线路数 593 → 848。
即：多圆弧的价值不在"省长度"，而在**把横向错位限制在局部 footprint 内**。

**5）在相同算法与预算下，多圆弧是否带来可观察的收益？**
是，而且非常大——但必须按 §6 的方式限定。可观察的事实是：
①同一框架/同一起点下，取消该自由度后有 197 条线路无法用紧凑几何表达，重新表达即 +2645；
②随后的同一 ALNS 只收回 483（20%），说明这些线路在受限语法下**没有更好的紧凑替代**；
③on 对照在同一搜索机制下从 1322 收到 1202（−120），off 组从 3967 收到 3484（−483），
搜索机制本身没有变差，变差的是**几何表达力**。

## 6. 因果性与局限（请务必连同 §0 的结论一起读）

**6.1 两组的"起点几何"并不相同——这是本实验最重要的限制。**
off 组为了真正取消多圆弧，必须先把 197 条继承线路在消融语法下重造，起点由 1322 变成 **3967**；
on 组则从原始的 1322 出发（它不需要重造）。因此**两组不是"同一初始几何 + 一个开关"的严格对照**，
而是"同一 3D 框架、同一 1024 连接、同一约束、同一搜索机制下，允许 vs 禁止该几何自由度"的对照。
**1185 与 3484 的全部差异不能都记在多圆弧头上**：其中 2645 是"重表达"的一次性代价
（它确实由禁令引起，但它衡量的是"继承几何在新语法下有多贵"，不是"优化质量"）。

**6.2 消融语法的解空间本身被改变（这是消融的语义，不是 bug）。**
"取消多圆弧"在数学上等于把候选几何集合从 `G` 收缩到 `G' ⊂ G`。起点解含 `G \ G'` 的几何，
所以任何严格的消融都必须先做一次投影。投影代价 +2645 是本实验最核心的测量值；
把它与"搜索收益"分开报告，才能避免把两件事混为一谈。

**6.3 与历史归档的偏差。**
on 重跑 1202 vs 归档 1185（+17，+1.4%）。原因：(a) 预算以墙钟计，事务序列不可逐位复现；
(b) 当前代码的贪心 sweep 与归档日志（`sweep round` / `sweep pass`）已不同，同预算下多接受若干次迁移；
(c) 归档 G4c_free 曾中断后 `--resume`。因此**因果比较以"同代码 on 对照"为主**，归档 1185 仅作历史参照。

**6.4 off 组的搜索预算少于 on 组。**
off 组 `G4c_free` 1836 s + `G4d` **158 s**（在安全检查点 `step_00009` 主动停止）= **1994 s**，
on 组为 3119 s。即 off 组被**欠搜索约 36%**。这使 3484 更像是"受限语法下的上界"：
给足预算它可能更低，但从日志看 off 组的收益主要来自贪心**高度迁移** sweep
（3967→3573，−394，52 次接受），随后 4 个 ALNS stage 分别为 −21 / 0 / −25 / −7
（接受率 7.5% / 0% / 10.4% / 5.2%），即 XY 重布本身已几乎没有收益；
继续跑不太可能回到 1200 量级。

**6.5 这不是"从零重新设计布线系统"的对照。**
若允许重新选择 fanout 落点、重新分配高度平面，使横向错位都 ≥2R，一个**没有**多圆弧的
系统本可以做得比 3484 好得多。本实验固定同一框架与同一起点，只隔离"平面多圆弧"
这一个几何自由度，因此结论应表述为：
**在该框架与该起点下，平面多圆弧带来约 2.9 倍的交叉差距，其机制是亚 2R 横向错位的紧凑表达。**

**6.6 未改动的部分（防止"降低难度"的质疑）。**
Validator、交叉口径（frozen strict D56 + ≥5° 豁免）、R15、玻璃尺寸、21 个物理高度、
1024 条连接、目标函数、ALNS / 联合让路 / 人工 U 策略、seed 全部未改；
两组最终解均由**冻结独立 Validator** 判定 PASS、0 violations；
off 组最终解的平面多圆弧区域数为 **0**（几何审计），即"取消"是真实发生的。
